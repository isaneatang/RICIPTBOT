11. NETWORK ADD/SWITCH BEHAVIOR
================================================================================

This is very important because some wallets do not have BOT Chain configured.

If the connected wallet is on the wrong network:

FIRST:

Attempt:

wallet_switchEthereumChain

If the wallet returns the equivalent of:

4902 = unknown chain

THEN attempt:

wallet_addEthereumChain

using the active network configuration.

After adding:

attempt wallet_switchEthereumChain again.

The user should see a clear explanation.

Example:

"BOT Chain isn't configured in this wallet. Add BOT Chain to continue."

Then the wallet should receive the network-add approval request.

After approval:

switch to BOT Chain.

IMPORTANT:

Do NOT make failure to switch/add the network look like failure to connect
the wallet.

These are separate states:

CONNECTED
WRONG NETWORK
ADDING NETWORK
SWITCHING NETWORK
READY
REJECTED

If the user rejects network addition/switching:

Keep the wallet session alive.

Do NOT disconnect the wallet.

Show:

"Network change cancelled. Your wallet is still connected."

This distinction is critical.

struct Passport {

Privacy
+
Verifiability

Gas cost.

43. TWO-COPY CONCEPT
================================================================================

Do NOT create two NFTs for one physical device.

There should be ONE Device Passport.

The physical device may move between owners.

Therefore:

Device
 ↓
ONE Passport NFT
 ↓
Owner A
 ↓
Transfer
 ↓
Owner B

The issuer can remain recorded separately.

This prevents duplicate ownership representations.

50. FINAL PRODUCT CONCEPT
================================================================================

The final product should communicate:

              PHYSICAL DEVICE
                     ↓
              PURCHASE RECORD
                     ↓
                  RICIPT
                     ↓
              DEVICE PASSPORT
                     ↓
                BOT CHAIN
                     ↓
             VERIFIED RECORD
                     ↓
              NFT OWNERSHIP
                     ↓
              TRANSFER TO BUYER
                     ↓
             PUBLIC VERIFICATION

RICIPT is not claiming that a blockchain magically makes a physical device
authentic.

It creates a persistent, transferable, cryptographically verifiable record
associated with the device.

Keep the product honest.

Keep the implementation simple.

Make the UI excellent.

Make wallet connectivity robust.

Make mobile browsers a first-class target.

And make the code easy enough for me to debug without needing to reverse
engineer a 10,000-line abstraction layer.
